# Airline Delay and Cancellation Data Analysis (PySpark)

## 1. Опис датасету та його характеристики
* **Датасет:** Airline Delay and Cancellation Data (2009–2018)[cite: 1]
* **Джерело:** [Kaggle Dataset](https://www.kaggle.com/datasets/yuanyuwendymu/airline-delay-and-cancellation-data-2009-2018)[cite: 1]
* **Обсяг:** ~5 ГБ, понад 50 мільйонів записів (у рамках лабораторної роботи детально опрацьовано дані за 2018 рік — 1.5 млн+ записів).
* **Основні колонки:** FL_DATE, OP_CARRIER, ORIGIN, DEST, DEP_DELAY, ARR_DELAY, DISTANCE, DEP_TIME, CANCELLED.

## 4. Висновки та рекомендації
1. Ефективність вбудованих механізмів оптимізації (Catalyst Optimizer):

У ході виконання лабораторної роботи було експериментально доведено критичну перевагу вбудованих функцій PySpark (when().otherwise()) над кастомними Python UDF. Бенчмаркінг показав колосальне прискорення (у 16.53 рази на користь вбудованих виразів), що обумовлено уникненням накладних витрат на серіалізацію та десеріалізацію даних між JVM та середовищем Python. Відтак, для забезпечення високої продуктивності при обробці великих обсягів даних (Big Data) слід за можливості уникати використання Python UDF.

2. Оптимізація зберігання та вибірки даних:

Використання колоночного формату зберігання даних (Parquet) у поєднанні з механізмом партиціонування за ключовими категоріями (OP_CARRIER) суттєво оптимізує дисковий простір та прискорює операції введення-виведення (I/O). Це дозволяє ефективно фільтрувати та читати лише необхідні підмножини даних без повного сканування всього масиву.

3. Аналітичні можливості розподілених структур:

Практично освоєно застосування складних агрегацій, SQL-інтеграції через тимчасові представлення, а також просунутих віконних функцій (Window Functions — ковзні середні, lag/lead, ранжування та оцінка варіативності). Це демонструє потужність фреймворку Apache Spark для вирішення прикладних завдань аналізу часових рядів та поведінкових трендів у масштабних розподілених середовищах.

4. Загальний підсумок:

Усі завдання базового (60%), стандартного (80%) та продвинутого (100%) рівнів успішно реалізовано та протестовано в середовищі PySpark 4.2.0. Проєкт повністю структуровано, задокументовано та готовий до подачі.
